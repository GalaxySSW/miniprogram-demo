# 判判

> 让 AI 理解一段关系。**不判你们谁输，只判误会有罪。**

判判是一个**双边情感调解 Agent**——微信小程序，程序内名称「爱情判官」。

情侣吵完架，一方发起立案，一张传票把另一方带进同一个案件；AI「猫猫判官」**分别**听完两个人，再输出一份双方共见的判决书和一个可执行的约定。它不判人对错，只判「误会」有罪。

## 问题：AI 只听过其中一个人

我们的自主调研（N=35）里，**80% 的受访情侣已经在向 AI 倾诉**，每周 2–3 次。但单人视角的安慰只能缓解情绪，改变不了关系——因为另一半从没被听见。

典型用户不是"关系破裂的人"，而是每天都在处理说不清的小事、又不想升级成大吵的普通情侣：

| 摩擦量级 | 频率 | 典型内容 |
|---|---|---|
| 微型摩擦 | 每天 | 回复慢 · 语气误读 · 家务 · 花钱 |
| 中型摩擦 | 每周 | 陪伴时间 · 社交边界 · 生活方式 |
| 重大争论 | 偶发 | 家庭 · 信任 · 前任 · 未来规划 |

他们打开判判的三个时刻：**我现在该不该回？怎么说才不继续吵？这是不是又发生了一次？**

为什么要赶在关系恶化前介入：Gottman Institute 对 3000+ 对伴侣、40+ 年的追踪显示，冲突互动模式在相隔三年后仍有约 80% 的稳定性。批评、蔑视、防御、冷战一旦固化，小事就会被记成"这个人不懂我"。

## 定位：不是聊天机器人，是同时服务两个人的调解服务

赛道位置是 **1v1 匹配之后的相处全流程**。别的产品从"认识"往后走，判判从"出问题"往前推。

```
市面上的 AI 陪伴      一个人 → AI → 安慰这个人      服务对象是个体
判判                  她 + 他 → 猫猫判官 → 同一份判决书 + 一个共同约定
                                                    服务对象是这段关系
```

四段服务链路：

| | 是什么 | 不是什么 |
|---|---|---|
| 01 自我认知 | 在真实冲突里看见：我到底在保护什么 | 不是做性格测试 |
| 02 破冰助攻 | 先回一句 / 递石子，在最难开口时替你迈一步 | 不是教第一句搭讪 |
| 03 沟通辅助 | 异步翻译 + 背对背追问，补齐双方盲区 | 不是讲沟通技巧 |
| 04 关系经营 | 约定追踪 + 复盘 + 重复模式识别 + 卷宗 | 不是签到打卡 |

## 机制来自线下调解室

这不是凭空发明的交互。婚姻咨询、人民调解、法庭调解里都有同一套成熟做法：调解员先分别单独听两边，再回到共同会谈给出结论。判判把这个角色 AI 化——**照搬它的机制，但故意不照搬它的气质**。

| 线下 · 调解室 | | 线上 · 判判 |
|---|---|---|
| 调解员 | → | 猫猫判官 |
| 单独会谈 | → | 背对背问话 |
| 把人请进调解室 | → | 一张传票 / 六位口令 |
| 共同会谈结论 | → | 双方共见的判决书 |
| 调解协议 | → | 本庭约定 |
| 事后回访 | → | 复盘与关系记忆 |

线下的三道门槛——要预约排期、单次数百到数千元、双方必须同时到场——在线上全部消失：三分钟发起，免费跑通一次完整调解，两人不必同时在线。

## 产品语言：「判」是外壳，「和」是里子

司法语言看上去在判谁对谁错，其实一个字都没判人。它唯一的作用，是让两个正在生气的人愿意点开第一次、并且愿意点开第二次。

| 情感化外壳 | 真正在做的事 |
|---|---|
| 猫猫判官 | 中立的 AI 调解角色。拟人形象容易被当成"在帮谁说话"，一只猫不站队 |
| 一张传票 | 把对方拉进同一个案件。「我们谈谈」很重，「我给你发了张传票」很轻 |
| 判决书 | 双方共见的同一份结论。判的是**那句话**，不是那个人——里面没有被告席 |
| 本庭约定 | 一个可执行的下一步。一方选定、另一方点头才算数 |
| 递小石子 | 非冲突期的轻互动。不必先开口道歉，台阶是产品给的 |
| 误会指数 | 全产品唯一的数字。只量"误会有多深"，不量"谁错得多" |

## 完整链路

两个人从不同时间、不同入口进来，系统始终在同一个案件里推进。

```
发起方   立案 → 传票预览 → 发出 → 背对背问话 → 看判决 → 定约定
应诉方   （几小时后）收到传票 → 应诉陈述 → 背对背问话 → 看同一份判决 → 点头
```

1. **先说这件事**（发起方）— 语音为主，打字 / 截图为辅
2. **发出前确认**（发起方）— TA 能看到什么，一目了然
3. **收到传票**（应诉方）— 只看中性案由，不看原话
4. **背对背问话**（双方）— 各自独立会话，互不可见
5. **判决与约定**（共见）— 同一份结论，双方点头

核心能力是**把攻击性的表达，翻译成对方能接住的诉求**。同一场冲突里，判判听到的是两种委屈：

> 小雯发出：「算了，你忙吧。」
> → 只给阿哲看：「我不是要你现在陪我。我只是想知道，我在你那儿排第几。」
>
> 阿哲回：「我不是说了在忙吗。」
> → 只给小雯看：「我怕一解释就变成吵架，所以挑了最短的一句——可它听起来最冷。」
>
> 他们吵的不是"回不回消息"，是"我在不在你心里排前面"。

## 技术架构

把调解员搬成 AI，难的不是对话能力，而是"同时对两个人负责"。三层为此设计：

| 层 | 能力 | 解决的问题 | 意义 |
|---|---|---|---|
| 数据层 | 双边数据架构 | AI 只听得到一边 | 案件绑定双方身份与情侣键，结论来自双边材料，而不是转发单人聊天 |
| 编排层 | 信息隔离的 AI 编排 | 原话会二次伤人 | 追问分两步生成——先出抽象方向，再只用当前方自己的话写问题，外加双重泄露过滤 |
| 记忆层 | 关系记忆与模式识别 | 每次都从零开始 | 主语是"你们"不是"某个人"；同类问题第三次出现时，主动提示换方案 |

如果只是 ChatGPT API 加一个人设 Prompt：无法背对背 · 无法保证不泄露 · 无法记得上次。

## 商业模式

调解结束会产出三样东西，它们分别承担获客、传播和留存，不需要额外买量：

- **传票** → 获客：一方发起，自然带来第二位用户
- **判决书海报** → 传播：脱敏长图可分享，一次和解一对多曝光
- **约定与石子** → 留存：到期回访，非冲突期也有互动理由

`新用户进入 → 免费跑通一次 → 付费管理长期关系 → 继续产出传播物 ↺`

| | 免费体验 | 季度会员 | 年度订阅 |
|---|---|---|---|
| 价格 | ¥0 | ¥39 / 季 | ¥169 / 年 |
| 内容 | 一次完整双边调解、判决书与一个约定 | 不限次调解、加急审理、精美判决书与特色传票 | 完整卷宗与关系年报、模式识别、定期复盘 |

市场测算：互联网婚恋市场 107 亿，判判 TAM（1v1 匹配后相处）81 亿，第一年目标 120 万——按季度会员客单 39 元估算，约需 3 万付费用户。

情侣是切入口，不是边界：**情侣 → 夫妻 → 亲子 → 室友 → 合伙人**。

## 后续规划：关系解读

调解只占吵架后的十分钟。要把留存做成可量化的长期指标，产品得在不吵架的日子里也有被打开的理由——这是闭环的最后一块。

**读出来。** 每次调解都在沉淀双方的语气、回应节奏和在意的点。累积若干次之后，可以从这些信号里读出各自的人格底色（比如一方是"确认型"，被不确定消耗，要的是提前告知；另一方是"回避型"，压力下先沉默，怕一解释就升级），并给出针对性的日常叮嘱，而不只是针对这一桩案子的判决。

**问下去。** 在架构上，这不是新增模块，而是把关系记忆层从「判决时才读」改成「随时可读」：

```
常驻提问入口        首页常驻，不必先立案
      ↓
双边隔离检索        只取「提问方本就可见」的材料，另一半的原话永不外泄
      ↓
关系记忆层（已有）   陈述 · 判决 · 约定 · 复盘 · 重复模式
```

入口从案件内移到首页，产品形态从**事件驱动**变成**常驻服务**。打开理由从"吵架才打开、月均 1–2 次"变成"追问 / 叮嘱 / 复盘 / 石子、周均"，留存因此有了四项可追踪指标：追问频次、约定完成率、误会指数趋势、关系月活。

场景从「吵架后的十分钟」扩到日常，人群也就从情侣扩到任何需要长期相处的关系。
