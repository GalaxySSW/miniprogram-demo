# ADR-0001：本地 mock 优先作为首轮演示基线

- 状态：Accepted
- 日期：2026-08-23
- 范围：开发、演示和首轮回归验证

## 背景

项目同时包含本地页面流程、云函数、外部 AI、微信权限和关系敏感数据。若直接把云端或真实 AI 作为每次开发的前置条件，调试会受到环境、密钥、网络和数据隐私的影响，也容易把“页面能点通”误判成产品已可用。

## 决策

默认使用本地 mock 完成首轮流程验证；云函数、真实 AI、真机权限、双账号和双设备作为独立验证层记录。任何功能只有在对应层级完成验证后，才能使用相应的完成口径。

## 结果

- Codex 可以在没有真实密钥和生产数据的情况下完成页面迭代。
- QA 记录必须明确是 `Mock verified` 还是 `Real verified`。
- 高风险功能仍需专项人工验收，不能因 mock 通过而直接发布。
- mock 行为与真实接口行为存在差异时，应在 Feature Spec 中明确记录。

## 备选方案

- 每次开发都连接真实云环境：反馈更接近生产，但成本、隐私和环境风险过高。
- 只做静态检查：速度快，但无法证明路由、状态和用户体验。

## 后续复审条件

当云函数、数据库和 AI 环境具备稳定 staging，且有双设备测试数据隔离后，再评估是否把 staging 冒烟加入默认门禁。
