# 功能 Spec：模型调用积分体系与账户额度

- 功能 ID：`2026-08-23-ai-credit-system`
- 产品负责人：待确认
- 风险等级：中
- 基线分支和提交：`rainno` / `4bdf528`

## 用户问题与目标

当前小程序可以调用多个 AI action，但没有可解释的账号额度、调用消耗和后台调配机制。需要建立一套 MVP 级积分体系，让用户知道本次调用消耗多少、还能使用多少，也让后台可以按账号发放、扣回、分配套餐和冻结额度。

积分是模型调用额度，不等同于人民币。第一阶段不接入支付、充值或订阅。

## 包含范围

- 每个微信账号拥有独立的模型调用积分账户。
- 按 action 或调用组扣除整数积分。
- 图片、语音和文本调用都能返回本次消耗与剩余额度。
- 模型调用失败、超时或结构化结果不可交付时，积分不应被最终扣除。
- 重复请求不会重复扣费。
- 后台管理员可以查询账号、发放积分、扣回积分、分配套餐、设置临时额度和冻结账号。
- 每次账户变更都有可追溯的原因、操作者和时间。

## 不包含范围

- 不实现微信支付、充值订单、退款订单或订阅续费。
- 不在客户端配置价格、套餐或扣费结果。
- 不把完整陈述、截图原文、语音原文或完整 Prompt 写入积分账本。
- 不在第一阶段实现复杂的按 Token 实时计费。
- 不改变 Home 功能和当前案件状态机。

## 用户流程与状态变化

```text
账号首次调用
  → 获得默认套餐/初始积分
  → 请求模型
  → 服务端计算费用并预扣
  → 调用成功：结算
  → 调用失败：释放预扣
```

用户侧必须能区分：

- 额度充足并成功生成；
- 额度不足，未发起模型调用；
- 模型调用失败，积分已释放；
- 重复请求，返回原请求结果，不重复扣费。

后台侧必须能区分：

- 正常余额；
- 预扣中的余额；
- 已冻结账号；
- 套餐额度和单账号临时覆盖；
- 每日/月度额度已达到上限。

## 数据、权限与隐私边界

- 账号主键为服务端取得的微信 `OPENID`，客户端不能指定计费账号。
- 费用由服务端根据 `action`、输入类型、模型标识和价格版本计算。
- 管理员身份由服务端白名单或后台角色校验，不接受客户端传入的管理员字段。
- 账本记录 requestId、action、模型、价格版本、积分变化和哈希，不记录完整用户陈述和 Prompt。
- MVP 第一阶段 `verdict` 和 `verdictDepth` 分别按 action 计费；当前 trial 还缺少可靠的 `caseVersion`、`trialRunId`、`billingGroupId` 和服务端案件所有者鉴权，暂不做合并计费。
- Phase 2 在补齐上述标识和服务端协调后，再评估将 `verdict + verdictDepth` 合并为计费组，避免并行调用重复收费。
- 账号余额、账本和调用记录不得通过普通用户接口任意写入。

## 验收标准

### 场景 1：正常模型调用

- Given 账号有足够可用积分
- When 用户发起一个文本、图片或语音相关 AI action
- Then 服务端根据 action 计算费用、完成预扣并调用正确的模型链路
- And 成功响应包含本次消耗、剩余积分、价格版本和 requestId

### 场景 2：额度不足或调用失败

- Given 账号可用积分小于本次最低费用
- When 用户发起模型调用
- Then 不调用外部模型，返回明确的额度不足状态
- Given 已预扣积分后外部模型超时、失败或 Schema 校验失败
- Then 释放或退回预扣积分，页面不能展示伪成功结果

### 场景 3：重复请求

- Given 相同 idempotencyKey 的请求已经完成或正在处理
- When 客户端再次提交相同请求
- Then 不重复扣费，并返回原请求状态或结果

### 场景 4：后台账户配置

- Given 管理员通过服务端身份校验
- When 管理员给账号发放、扣回、分配套餐、设置额度或冻结账号
- Then 账户聚合余额和不可变账本同步记录变化
- And 操作原因、操作者、目标账号和时间写入审计记录

### 场景 5：权限和隐私

- Given 普通用户尝试修改自己的余额或他人的余额
- When 请求后台管理 action
- Then 请求被拒绝且不泄露账户或案件的额外信息

## 未决问题

- action 积分基线是否采用报告中的 MVP 数值。
- Phase 1 的 `verdict` 与 `verdictDepth` 是否都按当前服务端 OPENID 计费；案件发起方归属延后到补齐案件成员鉴权后确认。
- 管理员先采用环境变量 OPENID 白名单，还是建立 `admin_roles` 集合。
- 微信云数据库当前环境是否支持满足预扣与流水一致性的事务/条件更新。
- 第一阶段是否需要在页面展示积分余额，还是只在失败时提示额度不足。

## 完成定义

- 规格、技术计划、任务清单和验证矩阵完成并冻结。
- 价格由服务端配置读取，客户端不能影响扣费。
- 正常、失败、重复、额度不足和管理员调整均有自动化或可复现验证证据。
- 没有接入支付，也没有使用真实用户数据做额度实验。
