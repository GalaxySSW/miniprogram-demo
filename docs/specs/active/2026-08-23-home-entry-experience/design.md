# 设计方案：关系首页与案件回访入口

## 设计目标

Home 要让用户在 3 秒内形成判断：

1. 我是不是来对地方了？
2. 我现在要处理哪一件事？
3. 如果我不想继续，怎么安全地离开？

视觉上延续现有“奶油纸、线稿猫、无衬线中文、克制色彩”的品牌方向；体验上从“功能菜单”升级为“关系状态的温柔中枢”。

## 评审整合后的设计范围

当前代码已有 19 个业务页面，Figma 已有品牌基础，但 UI Screens、Prototype、系统态和研发交付契约仍需补齐。因此设计交付分为三层：

1. 页面层：19 个业务页面的主态、入口、返回和 CTA。
2. 组件层：状态、权限、隐私、双方进度和安全边界的可复用表达。
3. 系统层：加载、失败、恢复、删除、邀请异常、AI 超时和安全干预。

本轮不新增独立 Landing Page；也不把独立案件详情页列为当前 P0。历史案件先通过卷宗卡片表达状态，并进入 `waiting / verdict / pact / review` 等现有目标页面。

## 视觉方向

### 基础色板

| 用途 | 色值 | 使用原则 |
|---|---|---|
| 页面底色 | `#FAF7F2` | 全局奶油纸背景 |
| 主文字 | `#1A1918` | 标题、主要按钮、关键结论 |
| 辅助文字 | `#6E685F` | 解释和次要信息 |
| 陶土橙 | `#C9573F` | 当前待办、传票、新进展 |
| 蜜色 | `#B0793F` | 等待、处理中、提示性状态 |
| 抹茶绿 | `#7E9B72` | 已和好、已复盘、已完成 |
| 细线 | `#E1DACE` | 分隔线、卡片描边 |

颜色只表达状态，不用颜色制造警报感。安全关系边界后续需要另做高对比状态规范。

### 排版

- 页面标题：40–56rpx，简体无衬线，字重 500。
- 区块标题：30–36rpx，字重 500。
- 正文：26–28rpx，行高 1.7–1.85。
- 辅助信息：22rpx，避免小于 20rpx。
- 主按钮：黑底奶油字，圆角胶囊，保持现有 104rpx 高度。
- 每屏只突出一个主操作。

### 视觉母题

继续使用“隐形纸条”：

- 新用户：一张尚未写下的纸条。
- 待办用户：一张被传回来的纸条。
- 历史用户：一叠已经整理过的卷宗。
- 关系记忆：纸条上反复出现的同一个词。

## Home 页面设计

### 结构骨架

```text
┌────────────────────────────┐
│ 判判                 卷宗  我的 │
│                            │
│ [状态主标题]                │
│ [一句解释]                  │
│                            │
│ [当前最重要的案件卡片]       │
│                            │
│ [主要操作]                  │
│ [次要操作]                  │
│                            │
│ 最近案件 / 本庭记得          │
│                            │
│ 安全与隐私说明               │
└────────────────────────────┘
```

### 新用户状态 `first-use`

视觉重点：大留白、猫、两句话和两个入口。

```text
判判

把说不清的事，
交给本庭。

双方分别说，
本庭只把共同需要听懂的留下。

[我要立案]
[我收到了传票]

原话不会互相展示
```

交互要求：

- `我要立案` 为唯一黑色主按钮。
- `我收到了传票` 为白底描边按钮。
- 不出现案件数量、关系绑定、付费和复杂功能入口。
- 传票输入可以通过弹窗完成，避免新建额外页面。

### 有待办状态 `action-center`

视觉重点：把待办卡片放在 Hero 下方或 Hero 位置，使用陶土橙左边线。

```text
本庭有一件事等你

TA 已经应诉了，可以开庭
2026 情字第 0822 号

[继续开庭]
```

次级任务以列表形式出现，每条只保留：

- 发生了什么
- 案件编号或主题
- 一个箭头

不要同时放多个黑色按钮，避免用户不知道先点哪个。

### 有历史无待办状态 `relationship-home`

视觉重点：最近一桩案件 + 一条关系记忆。

```text
本庭见过你们几次了

最近一桩
出行没提前说案
已和好 · 约定已复盘

[查看卷宗]

本庭记得
“提前说一声”已经出现过 2 次

[再立一桩案]
```

“本庭记得”只展示关系行为模式，不展示对个人的性格判断。

## 卷宗页面设计

### 信息层级

1. 案件标题和状态。
2. 案件编号和相对时间。
3. 共同约定或下一步提示。
4. 复盘入口。

### 列表卡片

卡片不使用大量图标，靠状态胶囊、左侧色线和简短文案区分。

```text
┌────────────────────────────┐
│ 出行没提前说案        已和好 │
│ 2026 情字第 0822 号          │
│ 约定：重要行程主动私信告知     │
│                         →    │
└────────────────────────────┘
```

对于未完成案件，卡片底部显示下一步：

```text
TA 已应诉 · 可以开庭 →
```

## 案件详情表达层设计

### 页面定位

首轮由卷宗卡片和现有目标页面组成“案件详情表达层”，不是另一个聊天页，也不是把所有数据重新铺开。后续如果卷宗卡片无法承载复杂状态，再评估独立案件详情页。

### 页面结构

```text
卷宗

出行没提前说案
2026 情字第 0822 号

[可以开庭]

案件时间线
✓ 你已经陈述
✓ TA 已经应诉
○ 等待共同开庭

本案摘要
一句脱敏案由

[开始开庭]
```

不同状态只改变卡片或目标页中的：

- 顶部状态胶囊
- 时间线完成节点
- 页面底部主按钮

不要为每个状态设计完全不同的新页面。

## 返回与导航设计

### 顶部导航

- Home：显示“卷宗”和“我的”。
- 卷宗 / 我的 / 状态目标页：左上角显示“‹ 首页”。
- 流程页面：左上角显示“‹ 返回”，回到上一步。

### 底部动作

完成型页面统一提供：

```text
[回到首页]
[查看卷宗]
```

主按钮采用黑色，次按钮采用白底描边。

### 状态反馈

- 加载：使用低干扰文字，如“正在调卷”。
- 失败：说明原因和下一步，不只显示“请求失败”。
- 空状态：说明为什么为空，并给出创建或重试入口。
- 退出流程：如果存在未保存内容，提示“先留在这里 / 放弃本次陈述”。

## 组件建议

首轮可以复用现有 `.card`、`.btn`、`.pill` 和 `cat`，建议补充：

- `PageScaffold`：页面安全区、标题、返回、状态槽位。
- `BottomActionBar`：主/次 CTA、loading、禁用、安全区。
- `AsyncStatePanel`：把 `RequestState`、`PersistenceState`、`RuntimeMode` 投影成用户可读的加载、失败、草稿和演示态。
- `PrivacyScope`：只有我、只有 TA、双方共同、公开脱敏。
- `SafetyIntervention`：暂停普通流程、退出和求助。
- `InviteStatePanel`：有效、无效、自己邀请自己、无权限、已关闭；过期、撤销、已绑定为设计预留。
- `PermissionPrompt`：相册、麦克风、保存相册权限。
- `RecoveryPanel`：冷启动恢复、案件不存在、版本冲突。
- `CaseStatus`：案件状态胶囊和状态文案。
- `ActorProgress`：我 / TA / 双方完成状态。
- `DeletionFlow`：删除确认、删除中、删除失败、删除完成。
- `EvidencePicker`：截图数量、上传、识别、失败和隐私提示。
- `HomeTaskCard`：首页首要任务卡。
- `CaseCard`：卷宗状态卡。
- `CaseTimeline`：案件进度表达。

这些组件优先作为小程序自定义组件或页面级公共片段，避免一开始引入新的 UI 框架。

### CatJudge 组件契约

现有 `components/cat/` 是唯一真实复用组件；问话页的 thinking 猫脸不应继续保留为独立内联结构。统一契约：

```ini
mood = calm / happy / sleep / thinking / alert
motion = static / breathe / blink
size = avatar / inline / hero / poster
```

品牌 Cat Symbol、产品 Mascot 和 Chat Avatar 可以保持形态层级差异，但必须共享线宽、比例和情绪语义。

## 跨页面系统状态设计

### 三维运行状态

```text
RequestState: idle → loading → success / failed / offline / timeout
PersistenceState: unsaved → saving → saved / draft-preserved / save-failed
RuntimeMode: cloud / mock / fallback
```

设计要求：

- 不用无限 spinner 代替解释。
- 明确数据是否已保存。
- 失败时优先提供“重试”和“回到安全位置”。
- Mock / fallback 必须有轻量但可识别的演示标记。

### PrivacyScope

```text
private-me       只有我能看到
private-ta       只有 TA 能看到
joint            双方共同看到
public-redacted  对外分享的脱敏内容
```

同一隐私组件在证据、传票预览、应诉、问话、判决、海报和我的页面复用。

### InviteState

至少设计以下状态：

- valid：正常进入应诉。
- invalid：说明口令不可用，允许重新输入或回 Home。
- self：同一账号演示模式，必须显式标记。
- unauthorized：无权限时不泄露案件存在性。
- closed：案件已结束，进入脱敏结果或回 Home。
- expired / revoked / bound：设计预留，待后端提供独立可验证状态。

### 安全干预

安全风险状态不能沿用可爱的普通判官语气。需要：

- 暂停当前审理。
- 简短说明“这可能已经超出普通沟通问题”。
- 给出停止、离开、联系可信任的人或当地求助渠道的可行动入口。
- 不要求用户继续上传更多敏感材料来证明风险。

### 删除与恢复

- 删除确认必须说明删除对象：原文、截图、语音、关系模式分别是什么。
- 删除中不能让用户重复点击。
- 删除失败要允许重试，不显示“已删除”。
- 冷启动恢复要说明“草稿还在 / 需要重新确认 / 无法恢复”。

## Figma UI 交付结构

品牌视觉与产品 UI 使用两个独立 Figma 文件。品牌文件只维护品牌定义与规范；UI 文件承载完整产品 UI：

```text
品牌 Figma：20260822_panpan_brand_design

UI Figma：20260822_panpan_UI_design
UI/
  Contract / Foundations / Components / Core Flow Screens
  Extended Screens / System States / Prototype / Handoff
```

每个页面必须标注：

```text
route / entry condition / actor / privacy scope / async state
failure & retry / back & cancel / data saved / qa-* selector / priority
```

Prototype 至少覆盖：

1. 正常双人主流程：Home → 立案 → 传票 → 应诉 → 判决 → 约定。
2. AI 或云端失败：输入 → 保存草稿 → 失败 → 重试 → 恢复。
3. 隐私或安全风险：触发提示 → 暂停普通流程 → 退出/求助。

## P0 / P1 设计优先级

### P0：双设备正式流程

- `home / evidence / statement / accept / preview / share`
- `respond / their-statement / interview / trial / verdict / pact`
- `waiting` 的双设备状态：发送、打开、应诉、完成、异常网络、缺席入口
- 隐私、AI 生成中、失败回退、双方进度和返回链路

### P0：本地 Mock 演示

- 主链路可快速完成。
- `waiting` 可用演示态推进，但不能伪装成真实双设备同步。

### P1：增强体验

- `reply / poster / pebble / history / review / profile`
- 站内提醒、订阅授权、细化权限拒绝和相册保存失败。

### P2：后续评估

- 独立案件详情页。
- 无障碍、大字号、深色模式和更丰富 Mascot 动作。

## 内容语气

- 主标题：短、确定、有一点拟人化。
- 状态文案：描述下一步，不评价用户。
- 失败文案：解释发生了什么，同时给出可恢复操作。
- 避免“你们的问题”“你应该”“本庭发现你总是”等带责备意味的表达。

推荐：

- “TA 已经应诉了，可以开庭。”
- “这桩案子还没有发给 TA。”
- “还没有需要复盘的约定。”

不推荐：

- “你们又吵架了。”
- “你的关系存在问题。”
- “本庭已经看穿了 TA。”

## 设计验收

- 新用户首屏能看懂两个入口。
- 老用户首屏能看懂唯一主任务。
- 历史卡片不需要打开详情就能理解当前状态。
- 卷宗卡片和目标页的主按钮始终只有一个。
- 页面返回不会把用户带回失效的旧案件。
- 视觉上不出现仪表盘、密集数据表或大面积渐变。
- 19 个业务页面都有页面契约，异常和系统态有统一组件承载。
- Figma 至少完成 UI Contract、组件状态和三条 Prototype 验证路径。
