# 功能 Spec：关系首页与案件回访入口

- 功能 ID：2026-08-23-home-entry-experience
- 产品负责人：判判项目组
- 风险等级：中高（涉及敏感关系内容、隐私范围、异步状态和安全边界）
- 基线分支和提交：`rainno` / `bb582bf`

## 用户问题与目标

当前小程序已经有 `pages/home/home` 和 `pages/history/history`，但首页仍然主要是“功能入口”，没有根据用户当前状态回答最关键的问题：

> 我现在应该做什么？上一桩案子到哪了？我怎么回到一个稳定的首页？

本功能将现有 Home 升级为“关系首页 / 案件中枢”，覆盖三类入口状态：

1. 新用户：快速理解判判，并在一次点击内开始立案或输入传票。
2. 有待办的老用户：优先看到当前最应该处理的事项。
3. 有历史但暂无待办的老用户：看到最近案件、关系中已沉淀的可行动记忆，并能进入卷宗。

核心目标：

- 降低首次进入的理解成本和操作成本。
- 让老用户打开小程序后直接获得“下一步”而不是重新寻找案件。
- 让历史案件按案件状态进入正确页面，而不是统一跳到判决页。
- 建立稳定的 Home、卷宗状态摘要卡、目标页和流程页返回关系。
- 保持“双方共同参与、原话隔离、关系记忆可删除”的产品原则。

## 评审整合后的最终判断

最新只读评审确认：页面路由层已经覆盖 19/19，当前缺口不在“再增加几个业务页面”，而在三个层面：

1. 跨页面系统状态没有成为一级设计对象。
2. 组件还没有形成状态、权限和隐私契约。
3. Figma 已有品牌 Design System 基础，但 UI Screens、Prototype 和交付标注还没有完整落地。

因此本功能最终采用以下范围：

- 不新增独立 Landing Page。
- 不把案件详情页作为当前 P0 新路由；首轮由 `history` 的状态卡片和现有目标页面承载案件详情表达。
- 将 `waiting`、`pact` 纳入双设备正式流程 P0；本地 Mock 演示可暂时跳过 `waiting`。
- 将 `reply`、`poster` 定为 P1 增强能力。
- 把系统态、组件契约和 Figma UI Contract 纳入正式交付，而不是只画正常态页面。

## 包含范围

### 1. 关系首页三态

- `first-use`：无案件、无草稿、无传票上下文的新用户。
- `action-center`：存在未完成案件、站内提醒或待复盘事项。
- `relationship-home`：存在历史案件，但当前没有高优先级待办。
- 本地 Mock 和云端数据都走同一套页面视图模型。

### 2. 传票/分享入口分流

- 从传票、分享或带有案件上下文的入口进入时，优先直达应诉流程。
- 不让被邀请用户先经过泛化的品牌 Landing 页。
- 普通打开小程序时进入 Home。

### 3. 案件列表与案件详情表达层

- 保留并升级 `pages/history/history`，展示真实案件状态、案由、约定和复盘状态。
- 首轮不新增案件详情路由，升级 `pages/history/history` 的案件卡片、状态摘要和下一步路由。
- 已有 `waiting`、`verdict`、`pact`、`review` 页面分别承载对应状态的详细内容。
- 后续若历史案件状态复杂到无法由卷宗卡片和目标页承载，再把案件详情页作为 P2 独立路由评估。

### 4. 统一返回链路

- 流程内返回：回到上一步，保留当前案件上下文。
- 顶层页面返回：回到 Home。
- 结案、约定、复盘等完成节点：提供“回到首页”和“查看卷宗”。
- 当页面栈不存在可返回页面时，使用 Home 兜底。

### 5. 首次进入的轻量说明

- 在 Home 的新用户状态中解释隐私和异步缓冲原则。
- 不新增绑定情侣、填写关系资料或强制 onboarding。
- 不新增独立营销 Landing 页作为首轮实现。

### 6. 跨页面系统状态

以下状态必须在产品和设计交付中作为一级对象覆盖，页面可使用弹层、全屏状态或内嵌状态，不默认增加业务路由：

- 隐私同意和外部 AI 数据处理说明。
- 安全风险干预和求助入口。
- 邀请无效、过期、撤销、已绑定、自己邀请自己、无权限、已关闭。
- 冷启动恢复、案件不存在、版本冲突。
- 离线、云端保存失败、AI 超时、可重试、Mock 回退、草稿保留。
- 相册、麦克风、保存到相册权限拒绝。
- 删除案件、删除中、删除失败、删除完成。
- 空卷宗、无通知、无判决、判决字段缺失。
- 约定冲突、TA 选择不同约定、重新选择。

## 不包含范围

- 不改造 AI Prompt、模型供应商或 AI 输出结构。
- 不新增账户系统、情侣绑定系统或独立用户资料体系。
- 不新增付费墙、订阅系统和支付能力。
- 不改变 `cases`、`pebbles`、`patterns` 的云端数据结构。
- 不把案件历史做成公开社区或可搜索内容。
- 不将本地 Mock 演示结果描述为真实双设备或生产数据能力。
- 不在本功能中实现暴力、胁迫等安全关系的完整外部转介系统；本功能必须提供入口级安全干预状态、停止流程和求助指引的设计契约。

## 用户流程与状态变化

### 普通打开

```text
普通打开小程序
        │
        ├── 有传票/分享上下文 → 应诉入口
        │
        └── 无上下文 → Home
                          │
                          ├── first-use
                          ├── action-center
                          └── relationship-home
```

### 新用户流程

```text
Home / 新用户
  ├── 我要立案 → evidence → statement → accept → preview → share
  └── 我收到了传票 → 输入口令 → respond
```

### 老用户待办流程

```text
Home / 当前待办
  ├── TA 已应诉 → trial → verdict
  ├── 判决已出 → verdict → pact
  ├── 约定待确认 → pact
  ├── 复盘到期 → review
  └── 递来石子 → pebble
```

### 历史案件流程

```text
Home → 卷宗 → 状态摘要卡
                  ├── 继续当前流程
                  ├── 查看判决
                  ├── 查看约定
                  └── 进入复盘
```

### Home 状态优先级

当多个事项同时存在时，首页只展示一个首要操作，其他事项作为次级列表：

1. TA 已应诉，可以开庭。
2. 判决书已出，等待查看。
3. 约定等待确认。
4. 约定已到复盘时间。
5. TA 递来石子。
6. 自己已完成陈述但还未发传票。
7. 等待 TA 应诉。
8. 无待办，仅展示最近案件和新建入口。

## 页面与交付优先级

### P0：双设备正式流程

- `home`、`evidence`、`statement`、`accept`、`preview`、`share`
- `respond`、`their-statement`、`interview`、`trial`、`verdict`、`pact`
- `waiting`：双设备正式流程 P0；本地 Mock 演示可跳过
- 以上页面的隐私、异步、失败、恢复、双方状态和返回链路

### P0：本地 Mock 演示

- 完整可演示主链路：首页 → 立案 → 陈述 → 传票 → 应诉 → 问话 → 判决 → 约定。
- `waiting` 可以用演示按钮或本地状态机快速推进，但必须明确“演示态”。

### P1：增强体验

- `reply`、`poster`、`pebble`、`history`、`review`、`profile`
- 站内提醒、订阅消息授权、异常网络和权限拒绝的精细化表达。

### P2：后续评估

- 独立案件详情页。
- 更丰富的关系生命周期工具、无障碍和深色模式。

## 数据、权限与隐私边界

### 数据来源

- 云端优先：`casedb.myCases()` 获取案件列表，`casedb.inbox()` 获取站内提醒。
- 当前案件流程：继续使用 `app.globalData.caseData` 保存短期流程上下文。
- 首页和卷宗不得把 `app.globalData.caseData` 作为历史数据唯一来源。
- 从卷宗状态摘要卡进入目标页后必须通过 `docId` 读取对应案件，避免打开另一桩案件的判决。
- `utils/casedb.js` 统一返回 `{ ok, data, source, error }`，页面不得用 `null` 猜测空数据或请求失败。

### 本地状态

可使用本地存储记录：

- 是否已经看过首次说明：`panpan.hasEntered`
- 最近一次打开的案件 ID：`panpan.lastCaseId`
- 已读提醒标记：沿用 `utils/notify.js` 当前机制

本地状态只用于体验优化，不能替代云端案件身份和权限判断。

### 隐私规则

- 首页、卷宗状态摘要卡不展示对方原话、聊天截图原图或语音原文。
- 历史列表只展示案由摘要、状态、共同约定和复盘结果。
- 不因用户进入 Home 就主动上传新数据。
- 删除关系模式和案件原文的现有机制保持不变。

## 验收标准

### 场景 1：新用户正常进入

- Given 用户没有案件、没有传票上下文
- When 用户打开小程序
- Then 进入 Home 新用户状态，看到一句产品解释、`我要立案` 和 `我收到了传票` 两个入口
- And 用户点击 `我要立案` 后进入现有 `evidence` 页面

### 场景 2：传票用户直达

- Given 用户从传票或分享上下文进入
- When 小程序解析到有效 `docId` 或口令
- Then 优先进入应诉流程，不要求先完成新用户介绍
- And 页面只展示对方可见的脱敏内容

### 场景 3：老用户存在待办

- Given `myCases()` 或 `inbox()` 返回待处理事项
- When 用户打开 Home
- Then 首页顶部展示最高优先级事项和唯一主按钮
- And 点击后进入该事项对应的下一页面

### 场景 4：老用户查看历史案件

- Given 用户拥有至少一桩历史案件
- When 用户从 Home 进入卷宗并点击案件
- Then 进入案件状态对应的目标页，而不是无条件进入判决页
- And 卷宗状态摘要卡已经给出正确的下一步操作

### 场景 5：空数据与本地 Mock

- Given 云函数不可用或返回空数据
- When 用户进入 Home 或卷宗
- Then 页面显示可理解的空状态或本地 Mock 状态
- And 不伪装成真实云端历史记录

### 场景 6：返回路径

- Given 用户从 Home、卷宗状态摘要卡或目标页进入流程页
- When 用户点击页面返回或完成节点的回首页操作
- Then 流程内返回回到上一步，顶层或完成节点回到 Home
- And 在页面栈为空时仍能通过 Home 兜底进入首页

### 场景 7：隐私边界

- Given 用户打开 Home、卷宗状态摘要卡或目标页
- When 页面加载数据
- Then 不显示双方陈述原文、截图原图和未经脱敏的模型输入

### 场景 8：邀请状态异常

- Given 用户通过传票或分享入口进入
- When 口令无效、自己邀请自己、已关闭或无权限
- Then 显示明确原因、重新输入/回 Home/联系发起方中的可用操作
- And 不泄露案件是否存在于其他用户名下

### 场景 9：异步与恢复状态

- Given 用户正在上传、保存、调用 AI 或等待另一方
- When 出现离线、超时、保存失败或页面冷启动
- Then 明确数据是否已保存、是否可以重试、是否保留草稿
- And 不用无限 spinner 或静默 Mock 结果掩盖失败

### 场景 10：安全风险干预

- Given 用户输入或选择内容触发安全风险提示
- When 判判无法把问题当作普通沟通冲突继续处理
- Then 暂停普通审理流程，展示明确、非评判、可行动的安全提示和退出/求助入口
- And 不把控制、胁迫或暴力包装成“双方再沟通一次即可解决”

### 场景 11：约定冲突

- Given 双方分别选择了不同约定
- When 系统发现约定不一致
- Then 展示“双方还没有选同一件小事”，允许重新选择或暂缓
- And 不自动替双方强行合并成一个约定

## 未决问题

1. 分享入口最终使用 `docId`、案件口令还是微信场景值作为唯一上下文？
2. 云端 `cases` 是否需要补充面向 UI 的 `nextAction` 投影字段，还是首轮由前端根据现有字段推导？
3. 隐私同意、AI 数据处理说明和安全干预是否采用统一弹层，还是部分场景使用全屏页？
4. 首次进入的隐私说明是否需要用户主动确认，还是采用可跳过的信息卡？
5. 真实双设备流程中，收到传票后是否需要订阅消息授权？
