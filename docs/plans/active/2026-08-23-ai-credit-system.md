# 实施计划：模型调用积分体系与账户额度

关联规格：[2026-08-23-ai-credit-system](../../specs/active/2026-08-23-ai-credit-system/spec.md)

## 允许修改的文件和目录

- `cloudfunctions/judge/`：requestId、计费编排、模型调用状态。
- 必要的 `utils/ai.js` 和现有 AI 页面：billing 返回、额度不足和失败状态。
- 确认事务边界后，再决定是否新增 billing 云函数或复用 judge/casedb。
- `docs/specs/active/2026-08-23-ai-credit-system/`：实现过程和验证证据。

## 不允许扩大范围

- 不接支付、充值、订阅或真实资金。
- 不修改 Home 主流程和案件状态机。
- 不把 API Key、完整 Prompt、原始陈述或真实用户数据写入文档/日志。
- 不上传、发布或切换生产云环境。

## 页面、路由、数据和云函数影响

- 页面：现有 AI 入口增加额度和失败状态，不新增业务路由。
- 数据：新增账号聚合、积分账本、调用记录、套餐配置和管理员审计数据。
- 云函数：服务端计算价格、预扣、调用、结算、释放和管理员鉴权。
- 模型：文本目标标识为 `deepseek/deepseek-v4-flash`；图片/语音遵循统一预处理链。

## 验证方式

- 先完成只读计量，不扣积分。
- 再用本地 Mock 模拟余额不足、重复请求、超时和 Schema 失败。
- 之后在微信开发者工具验证页面状态和账务响应。
- 真实云端、真实账户和支付场景需要单独授权和人工确认。

## 预期提交边界

规格冻结为一个边界；只读计量为一个边界；账本与管理员配置为一个边界。每个边界完成静态检查和运行时证据后再继续。
